# 2.4.1 · Clash 外观页修复

2.4.0 发布后，Clash 的「外观」分页只剩一句「这次操作插件没能完成：请重试」。本版只修这一处，Magpie 不变（仍 2.4.0）。

## 根因

`plugins/clash/backend.mjs` 里三条外观命令直接写了 `activate` 回调的参数：

```js
activate: async context => { … },
commands: { 'clash.appearance': () => readAppearance(context.storage), … }
```

`commands` 里的箭头函数是在模块作用域求值的，拿不到 `activate` 的参数，于是执行时抛 `ReferenceError: context is not defined`。插件 SDK 把认不出的异常折叠成 `COMMAND_FAILED`（避免把可能夹带地址或凭据的原文透给宿主），页面按码查表就只剩那句通用提示——所以看上去像「插件坏了」，日志里也没有具体线索。

同包内的 Magpie 侧用的是正确写法（`pluginContext = context` 存到模块作用域），未受影响。

## 修复

- `backend.mjs` 增加模块作用域的 `let storage`，在 `activate` 里 `storage = context.storage`；三条外观命令改读这个变量。
- 读取仍未变：`readAppearance` 在 storage 缺失或配置损坏时回落默认外观，页面照常打开；只有写入失败才报 `APPEARANCE_SAVE_FAILED`。

## 回归守卫

新增 `plugins/clash/backend-wiring.test.mjs`（3 条）：

1. `commands` 段里不允许出现 `context.`（注释除外）——这正是本次的坑；
2. 外观命令必须走模块作用域的 `storage`，且 `activate` 里有赋值；
3. `storage` 未就绪时读取回落默认值、写入明确报 `APPEARANCE_SAVE_FAILED`。
