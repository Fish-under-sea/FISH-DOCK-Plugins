# Magpie 插件 2.3.9

本版只修复 2.3.8 无法启动的问题，没有功能改动。Clash 保持 2.3.6，飞书保持 2.2.0；Magpie 仍要求 **FISH Dock ≥ 2.3.4**、宿主 API 1、Windows x64。

## 2.3.8 为什么装不上

2.3.8 的包能下载、校验通过，但插件进程一启动就被 Node 解析器终止，宿主在握手阶段收不到 `hello`，Dock 只能显示「更新失败（提交阶段）：握手阶段：插件进程已退出（退出码：None）」。真正原因是包内 `plugins/magpie/sdk.mjs` 的两处控制字符正则：

```js
// 2.3.8（坏）：caret 记法被当成了范围，\u007f-^_ 是倒序范围
if (/[^@-^_\u007f-^_]/.test(title)) throw new Error('title 不能包含控制字符');
// 正确写法
if (/[\u0000-\u001f\u007f-\u009f]/.test(title)) throw new Error('title 不能包含控制字符');
```

打包时用的 Dock SDK 快照把 `\u0000-\u001f` 导出成了 `^@-^_`，`\u007f-\u009f` 也一并变形。`\u007f` 到 `^`（0x5E）构成倒序范围，Node 22 与 Node 24 都会在模块加载阶段抛 `SyntaxError`，进程没有任何机会进入握手。同一文件的告警校验（`!/(...)/`）也被改成了 `[^@-^_\u007f]`，能解析但语义反转，等于校验失效。

## 修复

- SDK 从 Dock 仓 `fe36b7d`（2.3.8 同源提交）重新导出，与 2.3.8 的快照逐行比对只有这两行不同；重新打包后包内 `sdk.mjs` 与干净 SDK 逐字节一致。
- `magpie.exe` 未重新编译，仍是 `v0.1.4262+fish.35` / FileVersion `0.1.4262.35`，与 2.3.8 相同。
- `tools/verify-release.mjs` 新增一道语法门：归档内每个 `.mjs` 都用 `node --check` 解析一次，坏包在发版前就会被拒。用 2.3.8 的真实归档回归，现在会报「模块语法错误：plugins/magpie/sdk.mjs」。

## 验证

- `node --check`：包内 26 个 `.mjs` 全部通过（2.3.8 只有 `sdk.mjs` 一个失败）。
- 真实宿主 SDK 握手：用本版 SDK 暂存三个插件，跨工作目录完成 `host.hello` → `plugin.activate` → 视图读取 → `plugin.deactivate`，退出码 0。
- `verify-release`：76 个文件、ZIP CRC、逐文件摘要、目录与 npm 载荷一致；归档 48,060,597 字节，SHA-256 `cca0ad8da8783e24ce772ea05d42717216059e75760c7ff01bf3cd90d8093000`。
- 未做真实 Dock 安装验收；升级后请以插件卡能否正常显示与服务能否启动为准。

## 升级

直接更新 Magpie 到 2.3.9 即可，数据目录与已有知识库、Obsidian 配对、DuMate 配置不变。2.3.8 因为进程起不来，升级不会覆盖用户资料。
