# 插件 2.1.2

双插件版本：**Clash 2.1.0 → 2.1.2**、**Magpie 2.1.1 → 2.1.2**；飞书插件保持 **2.1.0** 不动。
要求 **FISH Dock ≥ 2.0.0**；建议配合 Dock **2.0.2**（宿主侧的错误码透传与插件日志是这一版体验的一部分）。

这一版的主题是**插件出错时能被看见**：过去插件失败只显示一句兜底话术、日志为零，Clash 还会出现「内核已停止但代理仍然有效」这种状态分裂。下面按插件分开写。

## Clash（2.1.2）

**内核运行态不再只存在内存里**
- 运行态落盘到 `config/run-state.json`（pid、端口、启动时刻、secret 指纹、订阅 id）。
- 插件进程重启后先尝试 **attach**：pid 存活 + secret 指纹匹配 + 控制器 `/version` 可达，三者都对才接管；接管后不会再起第二个内核。
- 坏记录、指纹不符一律丢弃，不误判。

**停止语义拆成两件事**
- `stop()` 先杀内核再恢复系统代理，返回结构化结果 `{kernel, proxy, code, message, ok}`。
- 系统代理恢复失败**不再阻断**杀内核，只是按错误码降级为告警（例如「内核已停止，系统代理恢复失败（PROXY_REGISTRY_WRITE_FAILED）」）。

**残留内核回收不再误杀进程**
- 原先「pid 存活」就结束进程；现在改为 pid + 实际启动时刻（±5 秒）+ 控制器可达三重判定。
- 控制器连得上 → 判为可 attach，**绝不发信号**；启动时刻对不上或取不到 → 判为外部进程，**也不杀**。
- 宁可留一个僵尸内核让用户手动结束，也不 SIGKILL 掉被复用了 pid 的其它程序。
- 启动时刻探测按 `FISH_PWSH → pwsh → powershell.exe` 候选链；全都不可用时把原因交给页面显示（`KERNEL_ATTACH_FAILED`），而不是静默失败。

**换节点后出口 IP 会刷新**
- 切换节点成功后同时清服务端 `ipCache` 与页面 `ip`/`ipAsked`，面板上的出口 IP、ASN 立刻换到新节点，不再残留旧值。

**校验错误全部挂码**
- 44 处裸抛的中文校验错误改为 `serviceError(CODE)`，**用户看到的文案一个字没变**，只是从「按中文正则猜」变成「按码查表」。
- 新增 28 个 Clash 校验码（`KERNEL_NOT_RUNNING`、`KERNEL_RUNNING_LOCK`、`PORT_RANGE_INVALID`、`SUBSCRIPTION_URL_INVALID`、`NODE_UNAVAILABLE`、`TUN_*` 等），每条都带「下一步做什么」。

## Magpie（2.1.2）

**端口先占后拉，消除 TOCTOU**
- `embedProxy` 的 listen 从流程末尾提到 `preparePortableRuntime`/`startChild` **之前**。原来「开头探一下、几十秒后才绑」的窗口没有了。
- 端口被占时在绑定阶段立刻失败并报 `PORT_IN_USE`，不再出现「magpie 已经拉起来、随后又被回滚」。

**绑定错误分码**
- `EADDRINUSE → PORT_IN_USE`、`EACCES/EPERM → PORT_BIND_DENIED`、其余 `UNKNOWN_ERROR`，原生错误挂在 `cause` 上；只对端口冲突做 120/240 ms 两档短重试。

**失败落盘与自愈**
- 启动失败写 `<插件数据目录>/gateway-error.log`，每行 JSON（时间、code、原生码、阶段、端口、文案）。写日志失败不覆盖原始错误；用户主动停止不进日志。
- 启动失败按 3 次退避重试（600/1500 ms），恢复即停手，用尽后定住并保留原因。

**运行时副本清理**
- 成功启动后清历史副本与过期的 `.binary-*`/`.data-*`（临时名有 10 分钟宽限期），只保留当前副本 + 1 份回选缓存。
- `gateway.json` 里指向已消失包目录的 `executable` 会被改指当前包路径。

## 共同部分

**错误码体系**
- `shared/errors.mjs` 扩到 **67 条**，覆盖 Clash 校验码、Magpie 服务码、协议层码与原生 Node 错误码（`EADDRINUSE`/`EACCES`/`EPERM`/`EBUSY`）。文案两两不同，每条含用户下一步。
- 页面按 `code` 查表显示，未知码才落到唯一的 `UNKNOWN_ERROR`「未识别错误」。**「请检查配置和运行状态后重试」这句兜底话术彻底移除。**

**协议层码收进码表**
- `COMMAND_FAILED`、`NOT_ACTIVE`、`UNKNOWN_METHOD`、`CAPABILITY_REQUIRED`、`BAD_HANDSHAKE`、`HANDSHAKE_REQUIRED`、`OPERATION_ERROR` 各有专属文案。

## 已验证 / 未验证

- 已验证：插件仓全量测试 **174 项 / 169 通过 / 0 失败 / 5 跳过**（跳过项为依赖真机环境的既有用例）；合并后码表 `shared` 与页面 `ERROR_TEXT` **67:67 同源**，在用 48 个码零遗漏。
- 未验证（留给 Dock 的 G1/G2 真机门禁）：真实 mihomo 内核的 attach / 停止、真实 Windows 注册表读写路径、3 秒 attach 冷却的真机手感、`pidStartedAt` 三条解释器路径。这些在合成夹具下全部通过，但没在真机跑过。

## 升级

- 从 Dock「插件」页「检查更新」直接升到 2.1.2；或在 Release 里下载 `clash.fish-plugin` / `magpie.fish-plugin` 手动导入。
- 飞书插件不需要动。
- `@fish-under-sea/fish-dock-plugin-*` 的 npm 单包同步发 2.1.2。
