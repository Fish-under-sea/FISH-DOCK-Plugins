# Magpie 插件 1.1.0：随包内置签到页，网关页可关自启动

适用于 FISH Dock 1.1.0+、Windows x64、宿主 API 1；网关页的「自启动」开关需要 FISH Dock **1.2.1** 及以后。仅 Magpie 适配插件升级为 **1.1.0**；飞书、Clash 和 OFM 保持已发布的 **1.0.2**。随包 Magpie 原生程序仍为官方 **0.1.1709**，原始字节和许可证保持不变。

## 改动

**签到页随包内置。** 签到页（`page-checkin`）不再只存在于 npm：插件产物里带一份目录副本，Dock 启动 Magpie 时以绝对路径通过 `MAGPIE_SEED_EXTRA` 注入，首启即装，离线可用。普通 Magpie 仍走 npm（出厂预置清单第 14 项 `@magpie-community/page-checkin@latest`），两条路径按包名去重，同一插件只装一次。

**页面写动作桥。** 页面侧新增 `magpie.act(name, params)`，宿主 `/api/plugin-pages/act` 只放行插件在 `magpie.actions` 里声明的动作。写动作必须放进 `magpie.actions` 的字符串项——旧写法 `magpie.writes` 不会被识别，签到开关与一键签到会全部 403。

**签到读写契约对齐。** `checkin:state` 现在返回「账号 key → 记录」的对象，并带 `credits`（账号 key → 实得积分），与页面读取方式一致。此前返回数组且没有 `credits`，页面会把所有账号显示成「今日尚未签到」、积分 0。

**网关页自启动开关。** 「启动服务」与「停止服务」之间新增 `自启动`：关掉它只是不再随 Dock 启动就拉起本机服务，眼下的服务照旧。状态由宿主持久化（`Installed.autostart`），插件页通过 `host.autostart` 读写；宿主早于 1.2.1 时这个开关自动隐藏，不影响其他操作。

**预置清单 14 项。** `DefaultSpecs` 增加第 14 项并把 `MAGPIE_SEED_EXTRA` 排在基础清单之前；种子 goroutine 移到 `Bun(ctx)` 错误判断之后，`PresetShipped` 注释改为准确表述（预置安装不随 preset 走，宿主启动恒定跑 `EnsureSeeded`）。

## 验证

- Go：`go build -tags nogui ./internal/{plugin,pluginrt,provider,gui}` 通过；`Seed`、`Checkin`、`PluginPageCheckin` 三组测试通过。
- 页面包：`node --test --test-isolation=none test/view.test.mjs` 7 项通过。
- Dock 侧：`node --test --test-isolation=none plugins/magpie/network.test.mjs shared/gateway.test.mjs` 通过；`stage()` 实测把 `page-plugins/page-checkin` 打进产物并计入 `plugin.json` 的 `files{}`。
- 环境性失败（与本次无关）：GUI 的符号链接用例（本机无 `SeCreateSymbolicLinkPrivilege`）、依赖 macOS keychain 的 Codex 用例、Windows 沙箱下的并发 rename 用例。

## 升级

Dock 用户在「插件」页检查更新即可；原生程序、账号与渠道资料保持原位。已安装旧版 Magpie 的机器升级后首次启动会装上随包签到页。
