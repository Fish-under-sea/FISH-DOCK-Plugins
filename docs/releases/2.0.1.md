# 四个插件 2.0.1

飞书通知、Clash 代理、Magpie 网关、OFM 本地模型升到 **2.0.1**，配套 **FISH Dock 2.0.0 及以上**。这一版收口 [插件仓 #11](https://github.com/Fish-under-sea/FISH-DOCK-Plugins/issues/11) 的两件事，外加三处实测出来的缺陷。

## 自启动只剩宿主插件卡一个入口

2.0.0 让插件卡和服务页各有一颗「随 Dock 启动」胶囊，两处写的是注册表里同一个 `autostart`，实测会出现「插件页显示未启用、插件卡显示已开启」的错位。2.0.1 把插件页里的那颗**整颗删掉**：

- Clash 概览的「系统信息」卡不再有「开机自启」行与切换按钮；
- Magpie、OFM 共用的服务页顶部不再有自启动胶囊（`shared/gateway-page.*` 与它的样式、用例一并删除）；
- 飞书本来就没有这个控件；
- 三个有本机服务的插件后端**仍然**读 `FISH_PLUGIN_AUTOSTART`——那是「随 Dock 启动」的实际执行点，删了自启动就真的失效。

宿主侧的三态按钮（红「关闭自启动」/ 蓝「随 Dock 启动」/ 绿「无需自启动」）是唯一入口。

## Magpie：上游追到 v0.1.2336，页面调用通道修回来

- 基线从 `v0.1.1709+fish.2` 追到 **`v0.1.2336+fish.3`**（`magpie v0.1.2336+fish.3`，FileVersion `0.1.2336.3`）。
- **修掉 2.0.0 的一处退化**：2.0.0 包里实际附的是上游官方 `0.1.1549` 未打补丁的 exe，它没有 `magpie.call` 通道，签到页的「关 / 开」「立即签到」与中转站探针的写动作发不出去。2.0.1 恢复自编译构建，`POST /api/plugin-pages/call` 按 `package.json` 的 `magpie.calls` 白名单分派，CSP 一行未改。
- 补丁重排的三个冲突点记在 [`plugins/magpie/tools/README.md`](../../plugins/magpie/tools/README.md)：`pluginPage` / `pluginPanel` 结构体加字段（上游新增 `Icon`、`Replaces`、`hosted`、`options`、`service`）、`pluginPageRoutes` 签名新增 `web bool`、`core_budget_test.go` 的预算常量以上游为准。

## Clash：两个实测缺陷

- **节点下拉不再「点一下很快消失」**。内核运行时页面每 1.2 秒轮询重绘一次，重绘整块换掉 DOM，原生 `<select>` 的展开列表挂在这个元素上，元素一换列表就没了——表现就是点开就消失、节点根本选不了。现在下拉展开期间不重绘，收起后补一次。页面版本 `1.4.0`（`page.html?v=1.4.0`）。
- **TUN 与普通模式不再互相占着端口**。两者写的是同一个控制器端口，先起的那个占着，另一个连不上，于是「只有一个能用」。普通模式起内核之前，先把 TUN 服务托管的内核交还（`job.ini` 置 0 并等它停），再 spawn 自己的内核。

## 已知未做

- **OFM 保持 2.0.0 的服务内容**（该插件 10 月 25 日暂停维护，本版只为它补版本号与自启动收口，不跟它自己的上游）。它上游的 `packages/standalone/backup.mjs` 已不存在，`stage.mjs` 与新结构不匹配——本版用 `--ofm-staged` 复用 2.0.0 已暂存的服务目录，暂存脚本的这个缺口留待恢复维护时一并处理。
- **宿主侧「拨到随 Dock 启动不立即生效」不是插件能修的**：`plugin_api.rs` 的 `dock.autostart` 只写注册表，拉起只发生在启动流程的 `resume()` 里，且 `resume()` 一个环节失败会跳过整批插件的自启动、只 eprintln。已开 [FISH-Dock#35](https://github.com/Fish-under-sea/FISH-Dock/issues/35)。
- Clash 的规则页、连接页仍是 JSON 摘要。
- `magpie.call` 通道与 `internal/relay` 探测仍靠 `fish.3` 补丁维持（上游至今只有读与页面选项），上游升级时要重排补丁。
