# Magpie 2.0.8

**只发 Magpie 一个包**（`magpie.fish-plugin` 2.0.8，exe `magpie v0.1.2336+fish.7`）。Clash 仍是 2.0.7，飞书与 OFM 仍是 2.0.1。

> 版本号跳过 2.0.6 / 2.0.7：这两个已经被 Clash 的两版发行用掉了，所以 Magpie 接在 2.0.7 后面。

## 上一版只改了签到页，这一版改的是整个窗口

2.0.5 换的那批 `logos/` 只服务于签到页自己。你在插件页和供应商页看到没变，是因为它们走的根本不是那条路：

| 界面 | 图标从哪来 |
| --- | --- |
| 签到页（自动签到） | `page/logos/<provider id>.*`，2.0.5 改的是这里 |
| 扩展 → 插件 | 插件市场给的名字 → exe 内嵌的 `assets/icons/<name>.svg`，或者插件包里自带的 `magpie.icon` |
| 模型 → 供应商 | 同上，经 `provider.PluginIcon` 落到 provider 的 `Icon` 上 |
| 侧边栏 / 路由 / 用量卡片 | 都是同一个 `Icon` 字段 |

所以只要在 `PluginIcon` 最前面加一层，四个界面一起换——这一版做的就是这件事。

## 素材编在 exe 里，不在插件包里

这是「用户一更新就掉」的根因：把图标放进社区插件包，插件一升级 `magpie.icon` 就回到原样。所以：

- 21 份素材编进 `service/magpie.exe`（`internal/provider/brandicons/`），由 `provider.PluginIcon` 优先返回；
- 开关只是 magpie 数据目录下 `icons/brand/on` 一个标记文件，关掉即回到原版，不删任何用户数据；
- 社区插件、页面的装卸与升级都不影响这一层。

覆盖 13 个预装插件注册的 21 个 provider id：

```
raccoon  autoclaw  autoclaw-cn  cline  codearts  kiro  loomy  loomy-plugin
minimax-code  minimax-code-global  mimo-app  opencode-zen-free
qoder  qoder-cn  qwenwork  qwenwork-enterprise
trae-cn  trae-global  workbuddy  workbuddy-ai  zcode
```

`joycode` 不在预装清单里，不动它。

## 一份素材，深浅自带

每份是一张 SVG，浅色那套在 `.l` 组、深色那套在 `.d` 组，用 `@media (prefers-color-scheme: dark)` 切换。窗口本来就跟着系统配色走（magpie 自己的 `app.js` 问的是同一个媒体查询），所以服务端不必猜当前主题，也就不存在「切主题要重发一遍图标」。

实测过（Chromium 156 headless + CDP 模拟配色）：`<img src="x.svg">` 里的媒体查询生效，SVG 里的 `<image href="data:image/png;base64,…">` 也渲染得出——所以 Trae、讯飞这类只有位图的，也能两套塞进同一个文件。

浅深切换实际看到的效果：

- Cline 黑螃蟹 → 白螃蟹
- OpenCode Zen Free 黑方块 → 白方块
- AutoClaw 黑底白 Z → 白底黑 Z
- 其余（Kiro 紫、MiniMax 红、CodeArts 红、WorkBuddy 绿、Qoder、MiMo 字标、ZCode、Trae 绿框）两套都清楚，原样保留

## 签到页的开关

自动签到页顶部多一行「**预装插件美化**」，右侧「关 / 开」，**默认开**。

它由签到页（`page-checkin` 0.2.5）通过两条新调用驱动：`brand:status` 读状态、`brand:set` 翻开关。宿主版本太旧、没有这两条调用时，整行不出现——摆个点不动的开关只会让人以为坏了。

## 其它

- exe 版本标识升到 `v0.1.2336+fish.7` / FileVersion `0.1.2336.7`；
- 补丁：`patches/magpie-v0.1.2336+fish.7.patch`（fish.6 → fish.7 的增量就是上面这层图标接管 + `PageCalls` 的两条新名字）；
- 核心脚本预算上调 268 字节并写明原因：`pluginpages.js` 里的 `magpie.call` 通道是页面在 CSP 沙箱里唯一的出口，属于核心而不是某个插件；
- 升级方式同前几版：**先卸载再安装**（宿主自更新的回滚点导出在 FISH-Dock#34 里还没修好），卸载会保留 `%USERPROFILE%\.fish-dock` 下的全部用户数据。
