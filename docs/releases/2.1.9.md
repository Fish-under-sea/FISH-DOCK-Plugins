## 二、Clash 2.1.9：首启自启动

### 现象与根因

「第一次开机自启动没起来，第二次就好了」。插件侧查下来是三处叠加：

1. `activate()` 里先 `await runtime.proxy.restore()`（要起一次 pwsh）、再 `await service.view()`（要 pid + 密钥 + `/version` 三重确认），最后才判断自启动。宿主给 `activate` 的冷启预算只有 5–8 秒（`DEFAULT_PLUGIN_ACTIVATE_SECS = 5`，冷启放宽到 8 s），开机那阵 Defender 正在扫、磁盘还在预热，这段很容易把预算吃光——`plugin-failures.log` 里那条「插件进程无响应（握手超时），已按未运行处理」就是这一刻。
2. `clash.json` 里的 `kernel` 指向**上一版插件目录**里的 `mihomo.exe`。升级换目录后那个文件没了，自启动那一次直接 `EXECUTABLE_MISSING`，而卡片上还写着旧地址。magpie 有 `repairPackagedExecutable` 兜这个，Clash 一直没有。
3. 起内核失败一次就结束，没有重试；冷启时端口/磁盘慢一拍就白等一天。

### 本版

- `activate()` 只做必要的事并**立刻返回**：自启动判定放到最前面，恢复系统代理改成后台（失败仍记一条日志）；
- 新增 `repairPackagedKernel`：`kernel` 指向包内、而文件已经不在了，就改回包内内核（`mixedPort` / `controllerPort` / `tun` 原样保留），用户自选路径不动；
- 自启动起内核按 **0 / 1.5 / 4 秒**各试一次，三次都失败才把原因写进日志；
- 未选过内核（`configured=false`）时仍然不替用户拿主意。

> 宿主侧还剩一段不归插件管：`activate` 的 5–8 秒预算与冷启阶段的 I/O 争用。已按证据在 Dock 主仓登记，见文末。

## 三、Magpie 2.1.9

### 1）#24：供应商页原生区分四类模型，模型列表只留 LLM

- `catalog.Model` 增加 `Audio`（TTS / 转写）与 `Embedding`（embedding / rerank）两个布尔，与既有的 `Draws` / `Films` 同一口径；`Chat()` 现在四类都不算「能聊的」；
- 站点列表里 `kind` 为 `audio` / `speech` / `tts` / `transcription` 与 `embedding` / `rerank` 的，各自落到 `Audio` / `Embedding`；只给模态、不给 `kind` 的按输出模态认；
- 插件侧：`capabilities.output` 里的 `image` / `video` / `audio` / `embedding` 直接映射到这四个布尔，**插件不用再改一次**；
- 供应商编辑页：原来的「图像模型」一块扩成**图像 / 视频 / 语音 / 向量四块**，样式、chip 组件与勾选逻辑完全沿用；每块有自己的一份「取消勾选」集合（`hiddenFilms` / `hiddenAudios` / `hiddenEmbeddings`），随保存落进 `providers.json`；
- 供应商列表与 Agent 的模型列表**只留对话模型**：列表构建处统一按这四个布尔过滤，媒体模型不再混进去挤掉能聊的模型。

### 2）#23：分组墙（2.1.8 已给，本版沿用）

`neartoken:state` 的 `groupList`（站点原文组名 + 倍率 + 该组能聊的模型数 + `ref`）与 `tokenName` 在 2.1.8 已经落地，本版没有改动，只是随 #24 的口径一起验过一遍。

### 3）预算

`core_budget_test.go` 的核心脚本上限按实测上调到 1,535,469（四个分区让 `app.js` 多了 1,040 字节），理由写在同一行的注释里。
