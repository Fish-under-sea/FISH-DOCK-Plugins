# Clash 2.3.6 — 看门狗改为隐藏启动（#50）

> 只发 Clash；Magpie 与飞书仍是 2.3.5，包未动。
> 校准：FISH Dock ≥ 2.0.0、宿主 API 1、Windows x64。

## 看门狗不再弹黑窗口（#50）

2.3.5 修好参数名之后，看门狗第一次真正建起来，也第一次把 `node.exe` 直接交给任务计划。任务计划在交互式会话（`LogonType=InteractiveToken`）里启动控制台子系统程序时会新建一个可见的控制台窗口，Node 的 `windowsHide` 管不到任务计划服务拉起的进程；Dock 内置的 `node.exe` 正是 `PE subsystem=3 (CONSOLE)`。结果是开启系统代理的瞬间，桌面弹出一个标题为 node.exe 路径的黑色窗口，并且一直挂着——看门狗常驻最长 12 小时，任务还设了每 5 分钟重复。

本版把任务动作从 `node.exe` 换成 `wscript.exe`：

- 新增 `plugins/clash/watchdog-launch.js`（JScript），由 `wscript.exe //B //Nologo //E:JScript` 拉起，再用 `WScript.Shell.Run(cmd, 0, true)` 以 `SW_HIDE` 启动 node；
- `wscript.exe` 是 GUI 子系统，自身不建控制台；node 的控制台窗口从创建起就是隐藏的；
- 启动器**等 node 退出**，任务实例在 `Running` 状态一直保持，`-MultipleInstances IgnoreNew` 才真正挡住 5 分钟重复触发（若启动器立刻返回，每 5 分钟会再起一个看门狗）；
- `//B` 是批处理模式：脚本自身出错时不弹「Windows Script Host」对话框，失败写 `<租约>.log`，与 `watchdog.mjs` 的失败日志同一份；
- 系统禁用 Windows Script Host（找不到 `wscript.exe`）时 `start()` 明确返回 `ok:false` 并记日志，**不退回**直接启动 node.exe——那正是本 issue 的窗口来源。

`watchdog-launch.js` 必须保持纯 ASCII：WSH 按 ANSI 读取无 BOM 的 `.js`，UTF-8 中文注释会吞掉下一行（实测 `'return' statement outside of function`）。单测断言文件里没有 >0x7F 的字节。

生命周期不变：系统代理接管成功才建任务，恢复成功、插件停止/关闭都注销；看门狗恢复完仍用 `schtasks /Delete` 删掉自己的任务。

## 升级

在 Dock 的插件页更新即可，无需重装 TUN 服务（本版没有改服务 exe）。若升级后仍看到黑窗口，先确认任务计划里 `FISH Dock clash watchdog-<SID>` 的动作是 `wscript.exe`——2.3.5 建下的旧任务会被 `Register-ScheduledTask -Force` 覆盖，但**只有在下次开启系统代理时**才会覆盖；想立刻生效，关闭再开启一次系统代理。

摘要见 `SHA256SUMS.txt`。
