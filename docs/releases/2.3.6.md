# 插件 2.3.6（Clash + Magpie）

> Clash 修 #50（看门狗黑窗口）；Magpie 修一处悬空引用并**追平上游到 `v0.1.3596`**（2.3.5 是 `v0.1.3383`）。
> 校准：FISH Dock ≥ 2.0.0、宿主 API 1、Windows x64。

## Clash 2.3.6 — 看门狗改为隐藏启动（#50）

2.3.5 修好参数名之后，看门狗第一次真正建起来，也第一次把 `node.exe` 直接交给任务计划。任务计划在交互式会话（`LogonType=InteractiveToken`）里启动控制台子系统程序时会新建一个可见的控制台窗口，Node 的 `windowsHide` 管不到任务计划服务拉起的进程；Dock 内置的 `node.exe` 正是 `PE subsystem=3 (CONSOLE)`。结果是开启系统代理的瞬间，桌面弹出一个标题为 node.exe 路径的黑色窗口，并且一直挂着——看门狗常驻最长 12 小时，任务还设了每 5 分钟重复。

本版把任务动作从 `node.exe` 换成 `wscript.exe`：

- 新增 `plugins/clash/watchdog-launch.js`（JScript），由 `wscript.exe //B //Nologo //E:JScript` 拉起，再用 `WScript.Shell.Run(cmd, 0, true)` 以 `SW_HIDE` 启动 node；
- `wscript.exe` 是 GUI 子系统，自身不建控制台；node 的控制台窗口从创建起就是隐藏的；
- 启动器**等 node 退出**，任务实例在 `Running` 状态一直保持，`-MultipleInstances IgnoreNew` 才真正挡住 5 分钟重复触发（若启动器立刻返回，每 5 分钟会再起一个看门狗）；
- `//B` 是批处理模式：脚本自身出错时不弹「Windows Script Host」对话框，失败写 `<租约>.log`，与 `watchdog.mjs` 的失败日志同一份；
- 系统禁用 Windows Script Host（找不到 `wscript.exe`）时 `start()` 明确返回 `ok:false` 并记日志，**不退回**直接启动 node.exe——那正是本 issue 的窗口来源。

`watchdog-launch.js` 必须保持纯 ASCII：WSH 按 ANSI 读取无 BOM 的 `.js`，UTF-8 中文注释会吞掉下一行（实测 `'return' statement outside of function`）。单测断言文件里没有 >0x7F 的字节。

生命周期不变：系统代理接管成功才建任务，恢复成功、插件停止/关闭都注销；看门狗恢复完仍用 `schtasks /Delete` 删掉自己的任务。

## Magpie 2.3.6 — 供应商编辑器打不开（`foldNeeded is not defined`）

### 现象

2.3.5 上点开任一供应商，Providers 页底部弹一个红色胶囊 `foldNeeded is not defined`，编辑器永远打不开。模型区一画就抛异常，整个页面停在错误提示上。

### 根因：补丁重放漏搬了一个 hunk

`foldNeeded` 是上游 `app.js` 里「模型芯片折叠」的模块级状态。fish.30 的两个相邻 hunk 是配套的：

| hunk | 位置 | 内容 |
| --- | --- | --- |
| `@@ -11141,8 +11162,6 @@` | 顶部声明区 | 删掉 `const foldNeeded = {}` |
| `@@ -11300,19 +11304,13 @@` | `drawFold()` 内 | 把 `measure()` 改成 `requestAnimationFrame(...)`，从此不再引用 `foldNeeded` |

fish.31 只搬了第一个，第二个整段丢了：声明没了，两处用法还在。`node --check` 只做语法分析（通过），`git apply` 干净应用（0 冲突），`follow-upstream.ps1` 只比对 hunk 数与树哈希（通过）——三重闸门都拦不住，直到运行时才 `ReferenceError`。

同一个缺口还漏了另一段：`renderModels` 里内联的 `kindNow` / `KIND_NAMES`（只有 Auto/Image/Video 三类）/ `pickKind` 没换成 `kindNowOf` / `openModelKindMenu`，于是 #42 的六类「Makes…」菜单在芯片右键上一直没生效（外层的六类表被内联的三类遮蔽）。

### 修法

- `drawFold()` 改成 `requestAnimationFrame` + 直接量 `scrollHeight`，不再依赖 `foldNeeded`（补丁里删掉声明与两处用法）；
- `renderModels` 的内联三件套换成 `kindNowOf` / `openModelKindMenu`，六类标注菜单真正生效。

基线从 `v0.1.3383` 走到 **`v0.1.3596`**（213 个 tag），补丁 `magpie-v0.1.3596+fish.33.patch`，158 文件 / 261 hunk，30 个冲突 hunk 逐条消化：

## 新增闸门：补丁「删了声明、还在引用」直接拒绝

`plugins/magpie/tools/check-assets-refs.mjs` 只看一件事：补丁的 `-` 行删掉了某个**顶格声明**，而补丁应用后的文件里**还在引用**这个名字。判据刻意收窄（不做作用域分析、跳过语言内建与宿主全局），误报接近零。

接在两处，任一处不过都不出包：

- `follow-upstream.ps1` 重放后检查，失败以退出码 3 停下并列出符号；
- `build-magpie.ps1` 编译前检查，失败 `throw`。

实测：拿 2.3.5 那棵树 + fish.31 跑，准确报出 `internal/gui/assets/app.js: foldNeeded（2 处引用）`；换 fish.33 则放行。

## 升级

在 Dock 的插件页更新即可。

- **Clash**：无需重装 TUN 服务（本版没有改服务 exe）。若仍看到黑窗口，先确认任务计划里 `FISH Dock clash watchdog-<SID>` 的动作是 `wscript.exe`——2.3.5 建下的旧任务会被 `Register-ScheduledTask -Force` 覆盖，但**只有在下次开启系统代理时**才会覆盖；想立刻生效，关闭再开启一次系统代理。
- **Magpie**：本版换了基线，`magpie.exe` 会以新的运行副本落盘（旧副本按既有规则保留一天再回收）。供应商编辑器恢复正常；芯片右键的「Makes…」菜单恢复六类（图像 / 视频 / 语音 / 转写 / 向量 / 重排）。

摘要见 `SHA256SUMS.txt`。
