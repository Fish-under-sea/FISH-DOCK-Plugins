# Magpie 插件 2.3.7

本版只更新 Magpie；Clash 保持 2.3.6，飞书保持 2.2.0。宿主要求 FISH Dock ≥ 2.0.0、宿主 API 1、Windows x64。

## 跟进上游

- 固定上游 `v0.1.4262`，提交 `30de93e9e9d5bf6a013b1773010700d8eaa707f0`。
- 原生版本 `v0.1.4262+fish.34`，Windows FileVersion `0.1.4262.34`、ProductName `magpie fish`。
- 保留现有页面调用、签到/探针、Purge、品牌图标、模型分类、媒体超时及素材 MCP。媒体设置改为按需加载，不提高上游核心脚本预算。
- 重新核对托管更新入口：移除更新控件，不切除普通配置、日志、命令行等设置行。

## 插件内独立知识库

新库位于插件持久数据的 `credentials/magpie-runtime/data/knowledge/github-capability-vault/`，不在安装包、exe 摘要目录或临时目录内。

首次启动从用户主目录下 `Documents/Obsidian Vault/github-capability-vault` 复制现有知识内容，逐文件校验后发布；存在已完成的新库时不重导、不覆盖新笔记。旧源不会自动删除，也不会通过 junction/symlink 把新库指回旧源。源目录缺失时建立空库并明确显示尚未导入。

原生短记忆放在库内 `memories/`，保留作用域、ID、状态、来源、锁、journal、手改保护与 digest；旧原生记忆保留恢复副本。长知识笔记保留目录结构，按需递归检索，不强塞进单条 2000 字的记忆。`memory_search` 可返回带路径和 Obsidian 链接的笔记引用；限定项目/类型/标签时不会擅自扩大为整库搜索。遗忘短记忆不删除知识笔记。

## Obsidian 专用插件

- 检测本机 Obsidian，并幂等登记新库，保留其他已登记库；每次服务重启不会自动弹出窗口。
- 随包部署 `fish-magpie-memory`：模型选择、多轮对话、找记忆、整理选文、另存新笔记和保存待审核短记忆。不依赖 Copilot。
- 首次使用仍需在 Obsidian 内允许社区插件；应用已打开时，可能需要重载/重启后才能加载新库及插件。不会修改应用的安全设置。
- 模型与供应商继续由 Magpie 管理。独立回环接口需要私有配对令牌，配对文件放在知识库外，供应商密钥不进入笔记或插件设置。
- 只有主动发送/整理所选内容时才调用模型；默认不上传整库、不覆盖原笔记。真实模型调用按所选供应商计费。

## 验证与限制

- 本地适配层、共享运行时及打包测试：130 项中 126 通过、4 项条件测试跳过；不将跳过项计为通过。
- 原生 `fishvault`、`memory` 和 `relay` 包通过；新增配对接口、作用域及路由守卫、核心脚本预算、媒体/记忆相关 gateway 测试通过。
- 生产程序隔离实测覆盖：页面权限、记忆落盘与知识笔记编辑后立即被 MCP 检索、私有令牌校验、模型调用路由、启动/停止/重启、旧页面 token 失效，以及两次独立静默保活、仅一次上游请求。
- `.fish-plugin` 与 npm 载荷使用 Node 22.23.4 制作，由仓库 CRC/ZIP/逐文件摘要校验器检查。归档 **47,788,595 字节**、73 文件，SHA-256 `e71638e5781b72f780919ceaab133e7ee7780a6d012365a7fbe517b0293a1b17`；与脚本生成的商店条目及 `SHA256SUMS.txt` 一致。
- **完整受影响 Go 包测试未全绿**：扩展运行中存在 Windows 符号链接权限不足、测试子进程临时目录约束、并发 rename 拒绝、其他平台/时序用例失败以及 gateway 包超时。未逐项在干净上游复现，不能一概称为上游问题；本版不删除这些断言，也不宣称完整原生套件通过。
- 未完成 Obsidian 桌面窗口内人工加载验收与全语言双浏览器回归；未调用真实付费模型。专用插件经本机合成供应商验证模型路由，不代表所有真实供应商都已逐一验证。

## 升级

通过 Dock 插件页更新 Magpie 后，启动服务完成首次知识库准备，再使用“在 Obsidian 打开”。确认新库内容完整后再自行处理旧 Documents 库；本版不会删除它。停用和卸载保留插件持久数据。
