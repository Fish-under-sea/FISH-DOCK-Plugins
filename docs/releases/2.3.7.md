# 插件 2.3.7（Magpie）

> Magpie 修网页模式下的「打开文件夹 / 选文件夹」死按钮（交接 `docs/handoff/2026-11-15-magpie-web-folders.md` 的 P0 + P1）。
> 校准：FISH Dock ≥ 2.3.4（选目录走宿主 `dialogs` 能力）、宿主 API 1、Windows x64。

## Magpie 2.3.7 — 网页模式的文件夹按钮不再弹红字

Dock 用 `magpie web --no-open` 起服务，管理页永远走 magpie 的**网页宿主** `webHost`。`webHost` 按设计拒绝「打开文件夹」和「选文件夹」，于是一批按钮点了只弹红字：

- `in the browser magpie can't open folders: it is <path>`——Library 的「Library folder」「Backups」、路径链接、Settings 的 Config folder「Open」、Sync 的「Show」、Data folder 的「Show」等；
- `in the browser magpie can't show a folder picker: type the folder's path`——Settings → Sync 的 Backup folder「Change…」，网页里没有可输入的框，是死按钮。

修复落在插件适配层，**在代理转发前接住**这些请求，在同一台机器上用资源管理器 / 原生对话框完成：

### P0：reveal 接力（7 条路由 + 1 个响应后处理）

新增 `plugins/magpie/reveal.mjs`，在 `embed-proxy.mjs` 的转发之前插入一层判断：

- **只对白名单路由**（`/api/library/reveal`、`/api/settings/reveal`、`/api/settings/log/reveal`、`/api/davsync/reveal`、`/api/autobackup/reveal`、`/api/datafolder/reveal`、`/api/gateway/held/reveal`）缓冲响应（上限 64 KiB，其余仍流式转发）。
- 上游 400 且正文是 `can't open folders: it is <path>` 时：从报错里取路径（**不采信页面传来的 `path`**）→ 展开 `~` → 拒绝相对路径、`\\?\`/`\\.\` 设备路径、非 WSL 的 UNC → `stat` 必须存在 → 目录用 `explorer.exe "<p>"`、文件用 `/select` 打开 → 回 `204`。
- 任何一步不满足（路径过期、被删、spawn 失败、文案不匹配）→ **原样透传上游响应**，用户至少还能看到 magpie 的原话。
- `POST /api/library/browser/setup` 的 200 响应若带非空 `revealError`，打开 `dir`、删掉字段、重算 `content-length` 回写——扩展弹层的「Show the extension folder」不再静默失败。
- **同源**（`reveal.mjs` 的 `sameOrigin`）是硬前提：`Origin` 为 `null`/不可解析、`Sec-Fetch-Site` 为 `cross-site`/`same-site`、或 Origin 不是本机同端口，一律 `403` 且**不碰上游**；远端 LAN / 隧道页面即使能直连也无法触发本机开文件夹。
- 开关 `FISH_MAGPIE_REVEAL=0` 整体关闭，回滚只改一行。

### P1：选目录（`POST /api/autobackup/choose`）

代理接住这个路由：

- 优先用宿主能力 `context.dialogs.chooseFolder()`（宿主 2.3.4 起，能力探测 `typeof context.dialogs?.chooseFolder === 'function'`）；
- 宿主缺席时退回 STA 的 PowerShell `FolderBrowserDialog`（`-NoProfile -STA`，无输出视为取消）；
- 用户取消 → `GET /api/autobackup` 取当前视图原样返回；选中 → `POST /api/autobackup/set {dir}` 原样返回。

## 能力与版本

- 清单新增 `dialogs` 能力（`tools/stage-development.mjs`）。声明它要求宿主 ≥ 2.3.4；本仓自 2.3.7 起声明，**旧宿主会拒装本插件**，这是显式取舍——网页模式的死按钮在旧宿主上没有可用的原生选择框。宿主能力缺席时仍有 PowerShell 兜底，但那需要宿主先装得上本插件。
- 不伪造 `web:false`：页面不会渲染终端、窗口、卸载等根本无法兑现的 UI，只修「点了会红」的文件夹类按钮。

## 已知限制

- Settings → Data folder 的「Move…」在非 portable 安装下才出现，它走 `POST /api/datafolder/move`，由服务端自己弹窗后立刻搬迁并重启进程，代理层无法把「已选好的路径」塞进去。Dock 默认 portable，该按钮当前不渲染；非 portable 用户仍会踩到，建议后续向上游提「web 模式接受路径参数」的入口。
- 上游改拒绝文案会让前缀失配（`REVEAL_REFUSED`）：集成/UI 测试跑在 pinned 二进制上，文案一变立刻红；本版本不引入启动自检（避免无谓的上游请求）。
