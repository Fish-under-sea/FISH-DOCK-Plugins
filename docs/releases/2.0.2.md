# Clash 2.0.2

**本次只发 Clash 一个包**（`clash.fish-plugin` 2.0.2，页面版本 `1.4.1`）。飞书、Magpie、OFM 仍是 2.0.1，包内容与 2.0.1 完全一致——不为版本号齐整去重打三个包，也就不会让它们再撞一次宿主那条更新失败的坑（[FISH-Dock#34](https://github.com/Fish-under-sea/FISH-Dock/issues/34)）。

## 修了什么

### 1. 节点列表往下滑，一松手就弹回顶部

内核运行时页面每 1.2 秒轮询重绘一次，重绘整块换掉 DOM，滚动位置跟着归零——往下滚一格、等一次轮询就被弹回去，65 个节点根本翻不到底。现在重绘前记下节点列表与代理组横条的滚动位置，重建后放回去。组卡横条同理，不再一刷新就跳回最左。

### 2. TUN 只能在停内核时改

2.0.1 之前，内核跑着的时候「TUN 虚拟网卡」那颗开关是灰的，只能「先停止内核 → 改设置 → 再启动」。现在可以直接切：后端把内核停掉、写配置、再按新设置拉起来，整段在后台跑（有 `tunSwitching` 状态，按钮显示「切换中…」，页面照常轮询进度）。

之所以必须重启内核：TUN 由 SYSTEM 服务托管，普通模式由插件自己 spawn 两个不同的进程，它们写的是同一个控制器端口，不重启换不过去。切换过程中会短暂断网，这是内核重启的固有代价。

失败有回音：TUN 服务没安装时直接拒绝并说明「请先在设置里安装 TUN 服务」，且**不会**先把正在跑的内核停掉；切换中途出错，错误写到卡片上，不会停在半开状态。

## 页面版本号与插件版本号是两回事

Clash 页头那行 `内核 v1.19.15 · 页面 v1.4.1`：

- **页面 vX.Y.Z** 是页面自己的缓存版本，`page.html?v=` 用它击穿旧缓存，跟插件版本不同步——页面没改的时候它就不动，插件升到 2.0.1 时页面还是 1.4.0，那是正常的；
- **插件版本**（2.0.2）在宿主插件卡和 `plugin.json` 里，页面在 iframe 里读不到它，所以不混在一起显示。

这次页面确实改了（滚动与 TUN），所以它跟着到 `1.4.1`。

## 升级

Clash 的 `credentials/` 里只有订阅地址与控制器密钥（几十 KB），不会撑爆回滚点，**用插件卡的「更新」可以直接升**；万一失败，卸载后重装即可，账号与订阅都在 `%USERPROFILE%\.fish-dock` 下，不会被删。
