# 插件 2.1.3

> 定稿：2026-11-02。版本位与发版说明在 t7 完成；`catalog` 的 `sha256` / `bytes` 待 t8 出包后回填，渲染产物由 captain 代跑 `render-readme`。

双插件版本：**Clash 2.1.2 → 2.1.3**、**Magpie 2.1.2 → 2.1.3**；飞书插件保持 **2.1.0** 不动。OFM 保持 **2.0.1**（暂停维护，不跟随）。
要求 **FISH Dock ≥ 2.0.0**；宿主 API 1；Windows x64。

这一版承接三条 issue：**#17（Clash 视觉与交互重构）**、**#15（签到页「今日积分」不实时）**、**#16（新装 Magpie 首启美化图标与页面不可用）**。三件合成一个发行范围，Clash 与 Magpie 各占一棵 worktree 并行施工，合并后统一升版。

### 设计取舍（本版有意为之，不是缺陷）

- **保存条回到表单末尾**（`position:static`）：560 宽下不再吸底压住 TUN 服务按钮，代价是要滚到表单底部才看到「保存内核配置」。本版选择「不遮挡可点控件」优先于「随时可见」。
- **概览卡片第三行由 `.pane` 内滚承接**：卡片等高、底边对齐；超出可视高度的部分交给页面内滚——这正是 `page.css` 自己写的契约「只在这里滚，不会多出一层宿主滚动」。
- **弹层用不透明底**：`backdrop-filter` 在没有 blur 支持的环境会退回半透明，能读出后面的「规则 / 全局 / 直连」；本版直接不透明底 + 细描边，视觉可预期。
- **下拉自绘而非原生 `<select>`**：原生弹层由系统绘制、与主题两套，且焦点在 `<select>` 上时页面不能重绘；自绘换来八态与完整键盘，代价是 `aria-*` 必须逐条验（已按 #17 §3 键盘表验过）。

### 视觉验收（12 张，dark / light 双主题实拍）

- 来源：`FISH-Dock-1102/reports/clash-visual/`（仓外夹具 + `capture.mjs`，Edge headless CDP 截图；夹具钉在 `03838d5`）。实拍由 captain 用 `danger-full-access` 执行——本会话受限沙箱禁命名管道、起不来 Chromium。
- 组合：`dark|light × overview|dropdown|settings × 900|560`，共 12 张；整页高度 **900×900 / 560×900**（恢复 `.pane` 内滚后不再随内容长到 1102 / 2010）。
- 逐项结论：
  - **分层与描边**：dark 下卡片靠内高光 + 描边分开，不再「糊成一片」；light 下白卡落在 `#f3f3f3` 上可辨，没有「白底白卡」。
  - **三态与读数**：延迟 good / warm / bad / 未测速四态在两种主题下都可区分；读数条与「更新于」时间戳在卡片内完整。
  - **下拉弹层**：不被 `.pane` 裁切，底色不透明、无透字。
  - **560 设置页**：TUN 服务三按钮完整可点，保存条在表单末尾（见「设计取舍」）。
- 复查轮次：t14（D1 卡片裁切 / D2 弹层透字 / D3 吸底条遮挡）→ t15（卡片等高）→ t16（恢复 `.pane` 内滚），三轮后重拍确认。

## 四、明确不做（本版范围外）

1. **服务层重构**：Clash 的 `service.mjs` / `runtime.mjs` / `tun.mjs` / `subscriptions.mjs` 一行不改；Magpie 的网关启停、端口分配、失败日志语义不动（#16 只优化重复摘要与状态可见性，不改启动流程结构）。
2. **RPC 改名**：Clash 与 Magpie 的 RPC 方法名、参数形状、`magpie.calls` 白名单一律不变。页面要的新能力只允许用现有方法组合实现。
3. **签名策略**：插件包签名 / 校验策略不变，不引入新签名格式，不改宿主准入逻辑。
4. **宿主侧改动**：Dock 仓的 `plugin_page.rs`（开页 SHA-256、持锁跑 RPC）与 `plugin_runtime.rs` 持锁优化不在本仓，本版不跟随，只在 #16 的「未验证」里记一条。
5. **Magpie 上游图标行为取证**：#16 的次要假设（`brandCache` 进程内缓存 + `pruneIcons` 的 keep 集合）需要上游 `internal/provider/icon.go` 全文与真机日志，本版不落结论。
6. **历史数据迁移脚本**：#15 的 400 改为原值透传后，历史台账里的 0 不追溯改写；若后续要补，走一次性迁移而不是读取侧改写，另开 issue。
7. **Magpie 后端批次（五项）**：删 400 补偿与读取侧改写、`CheckinViewState` 的 `RefreshedAt`/`Source`、`CheckinProviderState` 的 `Collector`、`brand:status` 的 `pendingPlugins`、`brandIconNames()` 扫目录 —— 已开成插件仓 issue **#18（`[P0][2.1.4] Magpie 后端批次`）**，在 2.1.4 出 `fish.9` 补丁 + 重编 exe 补齐。本版页面按「未告知 / 正在启动」降级，不假装已完成。
8. **`shared/dock.css` 自身的浅色盲区**（checkbox 的 `accent-color:#30d158`、`[role=alert]` 的 `#ff6b7a`）：属宿主共享层，Clash 页面本版用自带的 `--line-control` / `--c-bad` 绕开，不在本仓改宿主的样式基线（#17 §七 已把这层单独记账）。

## 五、构建门禁（结论：门 B —— 本版不重建 magpie.exe）

**结论**：2.1.3 不重建 Magpie 原生 exe，随包的 `magpie.exe` 与 2.1.2 **逐字节相同**（`v0.1.2336+fish.8` / FileVersion `0.1.2336.8`）。Magpie 后端五项（删 400 补偿与读取侧改写、`CheckinViewState` 的 `RefreshedAt`/`Source`、`CheckinProviderState` 的 `Collector`、`brand:status` 的 `pendingPlugins`、`brandIconNames()` 扫目录）全部转 issue **#18**，在 2.1.4 出 `fish.9` 补丁 + 重编 exe 补齐。

**为什么不做（理由）**：

1. 本机 `go` 不在 PATH，重建要先下约 75 MB 工具链（`plugins/magpie/tools/download-go.py`）+ clone 上游 `v0.1.2336` + 打补丁 + 两段式编译，链路长、失败面大。
2. 新 exe 在本环境**无法真机冒烟**：签到读取侧行为要真实账号与网络才验得出。把验证不了的二进制塞进 2.1.3，违反「只声明实际跑过的验证」。
3. 2.1.3 的 Magpie 价值集中在页面与 Node 适配层（前端去硬编码、首启可见性）。后端五项独立成批更清晰，也不拖累本版发版；到 2.1.4 一起出 `fish.9` 与重编，验证条件更充分。
