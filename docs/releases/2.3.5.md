# 插件 2.3.5（Clash + Magpie）

> Clash 合入 PR #49 并补一处竞态；Magpie 修 #48，并追平上游到 **`v0.1.3383 + fish.31`**（2.3.4 是 `v0.1.3240 + fish.30`）。
> 校准：FISH Dock ≥ 2.0.0、宿主 API 1、Windows x64。

## Clash 2.3.5 — 看门狗真正建起来，TUN 服务卸载后退休（#49）

- **看门狗计划任务从未建成。** `New-ScheduledTaskSettingsSet` 没有 `-DisallowStartIfOnBatteries` / `-StopIfGoingOnBatteries` 这两个参数，参数绑定直接失败，任务一次也没注册上。改为真实存在的 `-AllowStartIfOnBatteries` / `-DontStopIfGoingOnBatteries`，测试断言旧参数名不得再出现。
- **TUN 服务随插件卸载退休。** 插件卸载后，`%ProgramData%\FishDock\clash-tun` 里的服务不再常驻。
- **退休条件加固（本仓追加）。** PR 原实现读 `job.ini` 判断内核是否空闲：文件写到一半时，会把启动中的内核当成空闲，还会在内核进程仍在接管流量时撤掉服务（删掉运行中的 exe 并不会结束进程）。现在只看内核进程句柄：内核 exe 不在、子进程也已退出，才退休。

**已安装并点过「安装 TUN 服务」的用户：升级后请再点一次。** 服务 exe 是安装时复制到 ProgramData 的，不重装就仍是旧逻辑。

## Magpie 2.3.5 — 媒体模型的音频回退（#48）

`generate_audio` 用 NearToken 的语音模型时必定失败，报 `404 expected /v1beta/models/{model}:generateContent`。两个根因：

- **进程内直接调 `s.gemini`。** 那条路径依赖请求路由里的 `{call}` 参数，进程内调用时为空，于是 magpie 自己回了 404。现在解析 provider 后直连它的 Gemini API。
- **媒体模型被当成聊天模型，走了流式请求。** 走网关的转译路径时会请求 `streamGenerateContent`，NearToken 明确拒绝。现在音频工具发非流式 `generateContent`，请求体带 `responseModalities: ["AUDIO"]`，模型名不再带 `neartoken/` 之类的 provider 前缀。

两条路都失败时，错误会同时带出 `audio/speech`、`generateContent`、`chat` 三处上游原文，不再只给一句「没有可用音频端点」。只支持 chat 的模型（如 `suno/suno_music`）仍走 `/v1/chat/completions`，不会去问 Gemini。

## Claude Desktop 网关窗口没有中文：不是本版能修的

上游 `v0.1.3142` 那条说明是**记录问题，不是修复**；`v0.1.3383` 同样没有中文。本仓核对了 Claude Desktop 4.23118.0：

- magpie 接入时，Desktop 运行在网关（3p）模式，界面是安装包自带的 `ion-dist.asar`，只有 11 种语言，没有中文；主进程的语言表也没有中文。
- 每次启动，这个窗口都会从这 11 种语言里重新挑一种，写回 `Claude-3p/config.json`。magpie 写进去的中文会被 Desktop 自己改回 `en-US`。
- 有中文的是 Anthropic 账号登录的窗口。它在线加载 claude.ai 网页，对话只发往 claude.ai 自己的后端，不接受自定义网关；网关配置又只在 3p 模式下生效。

所以 magpie 无法让网关窗口显示中文。需要中文界面时，在 magpie 里断开 Claude Desktop，回到 Anthropic 账号登录；想用 magpie 的模型，可以接入 Claude Code 等客户端。magpie 的 Agents 页在 Claude Desktop 一行也会提示这一点。
