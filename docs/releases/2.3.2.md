# 插件 2.3.2（Magpie + Clash 同版）

> 两个插件同时到 **2.3.2**；Magpie 的 `magpie.exe` 重编到补丁 **`v0.1.3240 + fish.28`**（上一版是 `v0.1.3207 + fish.26`）。
> 校准：FISH Dock ≥ 2.0.0、宿主 API 1、Windows x64。

## Magpie：追平上游 v0.1.3240

- 基线 v0.1.3207 → **v0.1.3240**（33 个 tag）；
- 两处冲突手工消化：`providers.go` 的 `MarksServesKinds` 初始化字段、`docs/subsystems/gateway-routing.md` 的 #42 段落按上游新文重写。

## Magpie：provider 掉出后的 sticky 与恢复（#41）

插件重载、崩溃或安装窗口里「这次没报 provider」，以前会被当成移除，分组与页面跟着掉。本版：

- **A（上游已实现，本版验证）**：`keepUnloaded` 对「插件仍装着、这次没报」保留上次的 provider；
- **B**：插件清单可写 `magpie.keepListedUntilRemoved`，**默认保留、写 `false` 才关**（不改变上游对所有插件的默认语义）；
- **C**：专用恢复钩子 `neartoken:relist` → `provider.RestorePluginProviders(spec)`，只恢复 `PluginLeft` 记录（崩溃/卸载窗口类），**用户显式移除的不恢复**。

## Magpie：更新失败可见、首装进度（#41 的 P/Q）

- 安装失败落盘 `<data>/plugin-install-errors.json`，页面可点「重试安装」（`magpie:plugin-retry` / `POST /api/plugins/retry-install`，页面 call 与 GUI API 共用一份实现，安装进行中再点直接返回 `busy`）；
- 失败后自动换国内镜像重试一次（`NPMMirror`）；半装时清残留目录；单包失败不拖累其余；
- 首装逐包进度 `preinstallProgress` 与总进度弹窗：只挡 magpie 本页、失败三出口（重试 / 稍后 / 以后不再提示），装完自动解除。

## Magpie：设置页与素材 MCP

设置 → 图像的顺序改为：识图 → 生图 → **视频** → 语音 → 向量 → 识图 MCP → **素材 MCP**；生图 / 视频 / 语音 / 向量四行右侧各一个**响应超时胶囊**（`N 分钟 ▾`，与「默认/思考强度」同一套度量）。

- 新增 `videoModel`；生图与视频模型互斥；
- 四类媒体各用自己的超时（`imageTimeout` / `videoTimeout` / `speechTimeout` / `embedTimeout`），网关四条媒体路径全部接线；
- **素材 MCP**：端点 `/mcp/magpie/materials`（旧 `/mcp/magpie/image` 继续服务），工具 `generate_image` / `generate_video` / `generate_audio` / `generation_result`；三个工具各自取「设置里选的那个模型」；
- `generate_audio` 三级降级：标准 `/v1/audio/speech` → 同供应商 `chat/completions`（OpenAI 兼容的三种取音频形态）→ Gemini 原生 `generateContent` + `responseModalities:["AUDIO"]`；供应商没有音频渠道时给明确文案，不甩原始 500；
- 语音/向量行显示补齐为「图标 + 模型名 · provider」。

## Magpie：自启动适配（#45）

- `startWithBackoff` 对「`start` 抛错」与「返回 error 状态」同样按 0/600/1500 退避重试；自启判断与失败日志共用一份 `view` 快照；
- Clash 的 `autostartKernel` 把读配置 / 修内核路径与 `start()` 放进同一轮 0/1.5/4 秒重试，每轮只读一次 `view`，失败不抛 `activate()`。

## Magpie / Clash：数据根不再无界（#46）

- `usage.jsonl` 到 **128 MB** 滚到 `usage.jsonl.1`（先删旧 `.1`，Windows 才能 rename）；key 的日/月/总额花销上限**跨轮转仍正确**（窗口早于实时日志第一条时补读 `.1`），`log-v1.bin` 按文件身份自动重建；
- `masking` 保留期不再删**当天**文件（以前总量超限会把刚写的记录一起丢），当天也不占总量；`routing` / `masking` 在 `magpie web` 启动时各扫一遍（此前只有「再写一条」才触发清理）；
- 插件侧：旧名二进制（`magpie.exe` / `.exe.new` / `.before-*.exe`，一天宽限）、TEMP 残片（`tmp/magpie` 等，一天宽限）在启动前回收；`gateway-error.log` 滚动**先删 `.1`**；
- Clash：启动时清 `tmp/import-*` 与写了一半的候选配置；删订阅把 `credentials/<id>.json` 与缓存 YAML **一起删**，不再留 0 字节残片；
- 清理动作都写进日志（`[magpie] …清理` / `[clash] TEMP 清理` / magpie 侧 `routing:`、`maskrec:`）。

## Clash：系统代理恢复失败可诊断（#44）

- PowerShell 失败应答改为 `{ok:false, key, win32, message}`：键级失败报 `ProxyEnable` / `ProxyServer` / `ProxyOverride`，刷新失败单独报 `InternetSetOption`（带 `GetLastWin32Error()`）；
- 启动自愈、停止结果、看门狗三处日志都带键名与 Win32 码；看门狗写 `<租约>.log`（64 KB 封顶）并**保留租约**给下次重试；
- 恢复失败仍只降级，不拦内核启停与页面。

## 已知边界

- **Usage 页只读实时日志**：超过 128 MB 的旧明细（本机约 40 天）在 `usage.jsonl.1` 里，页面不展示；key 的花销上限不受影响。这是「有界」换来的，详见 `docs/maintainers/storage-budget-magpie.md`。
- **NearToken 的 TTS/音乐**：站点侧暂无可用音频渠道（500/503/404 `model_not_found`），magpie 已按 audio → chat → Gemini 原生三级降级；chat 通道取音频按 OpenAI 兼容三种形态实现，**成功响应样例仍未取得**，站点恢复后若返回自有格式需补一条分支（不改协议）。
- **#44 的原始样本根因仍未定性**：2026-11-03 那条日志没有可复现环境；本版起再出现会直接指出是哪个键/刷新调用、什么 Win32 码。
- 真机未点验：设置页新排版、首装进度弹窗、`generate_audio` 的真实音频返回、Clash 系统代理开关（出包后建议各过一遍）。
