## 二、本版改动（相对 2.1.4）

**Clash：两个下拉触发器首列文字对齐**（`d159d84`）

- 根因：`.combo-trigger` 原是 `justify-content:space-between`。代理组触发器只有 [图标][文字][箭头] 三个子元素，空余被均分，文字被推到中间；节点触发器多一个延迟（`margin-left:auto`）把文字压回左侧 → 两个并排的框文字起点差一大截。
- 修法：`justify-content:flex-start`，右侧那组整体贴右——**有延迟时由 `.trigger-delay{margin-left:auto}` 吃，没有延迟时由 `.combo-trigger:not(:has(.trigger-delay)) .chev{margin-left:auto}` 吃**；不新增占位元素。
- 第二处同源问题：`comboTrigger()` 里的 `.lb-ico` 原是**按条件渲染**（节点名是 `DIRECT` 这类没有 emoji 时就没有图标盒），首列又少 24px → 改为无条件渲染，与「选项行的 emoji 一律进 16px 盒」同一条规矩。
- 实测：两个触发器的 `.trigger-text` 相对各自左边缘偏移 **37px = 37px**（37 = 边框 1 + 内边距 12 + 图标盒 16 + gap 8），900/560 两档与弹层展开态一致。
- 测试：`plugins/clash/*.test.mjs` 137 项 / 134 通过 / 3 环境 skip / 0 失败，新增一条静态用例钉住「`flex-start` + 图标盒不许条件省略」。

## 三、为什么是重发而不是改 2.1.4

`v2.1.4` 的 tag、GitHub Release 资产与 npm 三个包都已发布，**已发布产物不可原地替换**（下游按 `sha256` 校验，仓库里也有引用）。因此按补丁版处理：main 上合入 `d159d84`，三插件统一升 2.1.5，重新出包、回填目录、发 Release 与 npm。

同时修正一处流程漏洞：**t9 收尾只核了"版本位改齐"，没有核"每条已合入的修复是否都进了 main"**。2.1.4 期间 `feat/214-clash` 上最后一个提交（审查后追加的对齐修复）没被合并，而收尾成员在写发行说明时把它当成已完成。后续版本收尾必须做一次 `git log --oneline main..<每条功能分支>` 为空校验——已在维护者指南的收尾清单里补上这一条。
