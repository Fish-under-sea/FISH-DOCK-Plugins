# Magpie 2.2.9

> 插件版本 **2.2.9**；`magpie.exe` 补丁基线 `v0.1.3140 + fish.24`（文件版本 `0.1.3140.24`）。
> 校准：FISH Dock ≥ 2.0.0、宿主 API 1、Windows x64。

本版三件事：**两个内置页面插件收成一个**（解耦后重新内置）、**新增内置破甲**、**#36 四项进宿主补丁**。另有 #37 的日志落盘。

## 一、签到 + 中转站探针 → 一个插件

- 新包：`@fish-under-sea/magpie-checkin-relay-probe@1.0.0`，单独维护在
  [`Fish-under-sea/magpie-checkin-relay-probe`](https://github.com/Fish-under-sea/magpie-checkin-relay-probe) 与 npm 同名包。
- 形态：**一个页面插件、两个页面**，页内标签切换（签到 / 中转站探针）；侧边栏名称 **签到&探针**，
  图标沿用签到那套（`page/icon.png` + `page/icon.svg`）。
- 两页的页面代码、图标、样式、各自的测试**原样搬入**（`page/checkin/`、`page/relay/`），
  新增的只有切换壳 `page/index.html` / `app.js` / `style.css` 与转发层 `page/relay.js`。
- 为什么是帧：两页都按「整个文档就是我」写（全局 id、各自样式表），同文档必互相踩；
  帧里的 `bridge.js` 连的是本页，所以 `relay.js` 把子帧消息换成新 id 转发给 magpie 窗口，
  回程换回原 id，主题/可见性事件广播给两个帧（单测 8 条覆盖）。
- **升级迁移**：`plugins.json` 里旧的 `page-checkin` / `page-relay-probe`（npm 名或旧包内的绝对路径）
  整条删除，新条目按稳定路径写入；用户在这两条上设过的 `off` 与折叠状态随新条目保留。
  不删旧目录里的任何用户数据。

## 二、新增内置破甲

- `@fish-under-sea/magpie-purge@0.3.1` 随 Magpie 包分发，首启同步到
  `<magpie 数据>/plugins/magpie-purge` 并以绝对路径登记；页面与网关钩子都从本地目录加载，离线可用。

## 三、#36 入宿主补丁（fish.24）

1. **重列钩子**：插件页的「刷新」现在会让宿主再列一次插件模型
   （`plugin.Providers`，与供应商编辑器「获取模型」同一条路径），点完 ≤5 秒即可看到
   `plugin-providers.json` / `cache/providers-state.json` 的 models 数变化。
2. **交接防抖**：`handOver` / `settle` / `dropHostProvider` 只认「插件自己列出来、且那条
   `signedIn == true`」；不再在删除时 `catalog.SaveLive(..., nil)`。`providers.json` 的
   `deleted[]` 不再出现「删→建→删」增长。
3. **分组语义**：`ModelIDs()` 只认模型名（宿主模型平面没有分组维度），口径钉在插件契约上——
   插件只在「该模型所有分组都停用」时才写条目；部分分组停用留在页面自己的明细里。
   新增测试固定这一条。
4. **旧 options 清理**：启动网关时清一次 `@fish-under-sea/magpie-neartoken` 的
   `disabledModels` / `enabledByGroup` / `disabledByGroup` 三个键；只动这个包，别的插件同名选项不碰。

## 四、页面宿主支撑（合并件必须）

- `frame-src` 放行**页面自己目录**（此前是 `'none'`）；
- `_magpie/bridge.js` 在页面目录的**任意深度**都可取（子帧在 `checkin/`、`relay/` 下）；
- 页面文件补 `Access-Control-Allow-Origin: *`：sandbox 帧是不透明源，`type="module"` 脚本以
  `Origin: null` 取文件，没有这条整个脚本不执行（中转站探针页本来就是 module，之前也受这条影响）；
- 页面响应**不再带 `frame-ancestors`**：Chromium 不拿任何源与不透明祖先做匹配，`'self'`、地址、
  路径源、`*` 都会把子帧拦成 `ERR_BLOCKED_BY_RESPONSE`。页面 URL 自带 32 位一次性 token，
  且页面无表单、无导航、无网络，风险面收在这里。

## 五、#37 日志落盘

- 适配层把 `magpie.exe` 的 stdout/stderr 同时写 `<插件数据目录>/magpie.log`：
  单文件 1 MB 滚动、保留 `.1` 一份，每次启动先落一行分隔（时间、端口、网关端口）。
- `gateway-error.log` 保持原样（只记启动失败 JSON）；`host/plugin-logs/fish.magpie.log` 仍是适配层自己的输出。

## 七、已知边界

- `frame-ancestors` 取消是**为内嵌帧让路**的取舍，见第四节；如果以后要恢复，得让 magpie 的窗口
  以非 sandbox 方式托管插件页，那会打开更危险的口子（同源可读 /api）。
- 分组的「部分停用」仍不会反映到 magpie 模型清单；这是宿主模型平面没有分组维度的直接结果，
  不是本版的遗漏。
